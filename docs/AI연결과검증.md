# AI 연결과 검증

2026년 10월 23일 기준으로 문서 분석 API, 근거 검토·승인, 기획 초안 API와 화면을 구현했습니다. 실제 유료 모델 호출은 수행하지 않았습니다. 공개 체험 화면은 가상 예시를 사용하며 서버에 저장하지 않습니다.

## 구현한 흐름

1. 로그인한 사용자의 회사·프로젝트·원본 접근 권한을 확인합니다.
2. 원본의 업로드 완료 상태, 파일 시그니처와 용량을 재확인합니다.
3. 설정한 모델이 PDF·이미지와 구조화 출력을 지원하는지 현재 AI Gateway 목록에서 확인합니다.
4. 분석 작업을 기록한 뒤 원본을 Vercel AI Gateway를 통해 모델 제공사로 전송합니다.
5. 결과는 검토 대기 근거로 저장합니다. 자동 승인하지 않습니다.
6. 사용자가 원본 페이지·대상·기간·결과·수치·단위를 대조하고 필요한 내용을 수정·승인합니다.
7. 서버가 해당 제품의 승인된 근거만 읽어 상세페이지 기획 초안을 생성합니다.

AI 생성은 40초 제한, 자동 재시도 0회로 설정했습니다. 동일 원본의 동시 분석은 데이터베이스에서 차단합니다. 중단 후 15분이 지난 작업은 다음 분석 요청에서 실패 상태로 정리합니다. 결과 저장 도중 오류가 생기면 이미 등록된 검토 대기 근거가 있을 수 있어, 재분석 전 이를 확인하도록 안내합니다.

## 운영 연결 전 필요한 설정

기존 Vercel 프로젝트의 Preview 환경만 사용합니다. 기존 운영 제공 중지 상태를 임의로 해제하지 않습니다.

- `ENABLE_EVIDENCE_WRITE=true`: 승인된 데이터베이스 변경 적용과 권한 검사 후 설정합니다.
- `AI_GATEWAY_MODEL`: 현재 Gateway 모델 목록에서 PDF·이미지 입력과 구조화 출력을 지원하는 정확한 모델 ID를 선택합니다. 기본 모델을 코드에 고정하지 않았습니다.
- 인증: Vercel 배포에서는 OIDC를 사용합니다. 로컬에서 실제 요청을 검증할 때만 `AI_GATEWAY_API_KEY`를 비공개 환경 파일에 설정합니다. 키는 채팅이나 저장소에 넣지 않습니다.
- Gateway의 실제 지출 한도와 사용자 승인 비용 범위를 먼저 설정합니다. 원본의 외부 AI 제공사 전송 범위도 확인해야 합니다.
- 위 설정과 비용 승인 후에만 `ENABLE_AI_ANALYSIS=true`로 설정하고 Preview를 다시 배포합니다.

현재는 AI 사용을 비활성화했습니다. 과금 없는 단위·API 모의 테스트와 공개 체험 화면 검증을 실모델 통합 테스트로 보고하지 않습니다.

## 데이터베이스 변경

사용자가 [AI 근거 저장 권한 추가안](AI근거저장권한추가안.sql)을 승인했고 `phase_b_analysis_evidence_permissions_and_guards` 마이그레이션으로 적용했습니다. 기존 정책과 자료는 유지했습니다.

추가한 것은 분석 작업 INSERT·UPDATE와 검토 대기 근거 INSERT 정책 세 개, 원본별 활성 작업 중복 방지 인덱스, 작업 식별 정보 변경 방지, 검토된 근거 덮어쓰기·검토자 위조 방지 트리거입니다. 승인 근거를 수정하려면 별도 버전 관리 설계가 필요합니다.

실제 DB 권한 검사 13개를 통과했고 임시 자료는 모두 롤백했습니다. 보안 점검 경고는 0건이었습니다.

## 기획 초안의 범위

전성분에 표기된 성분만 분석에 포함하고 승인된 근거 ID만 연결합니다. 거품형 세정 제품의 거품 구좌, 마무리 구좌 정확히 하나, 추천 대상 → 마무리 → 사용방법 → 제품 연출 순서를 검사합니다. 연결 근거에 없는 수치·단위와 일부 과장 표현도 차단합니다.

자동 검사는 원문 일치나 표시광고 적합성의 완전한 보증이 아닙니다. 모델이 적은 인용문을 원본과 대조하는 사람의 검토가 필요하며, 기획 초안도 카피·근거를 검수해야 합니다.

기획서 편집·구좌 승인·전체/개별 재생성·버전 복구·HTML/JSON 내보내기 코드를 추가했습니다. `/api/plans`와 별도 `planning_versions` 저장소를 사용하며 기존 `sections`를 덮어쓰지 않습니다. [버전 저장 추가안](기획서버전저장추가안.sql)은 사용자 승인 후 실제 Supabase에 적용했고 실제 권한 검사 19개를 통과했습니다. 임시 자료는 모두 롤백했습니다. 로컬의 `ENABLE_PLAN_STORAGE=true`를 활성화했으며 Preview는 배포 재개 승인 후 반영합니다. 실제 로그인 계정 검증은 사용자가 계정 설정을 나중으로 선택해 남아 있습니다.

개별 재생성에는 해당 버전의 기준 브리프, 핵심 구매 이유, 전략, 선택 구좌, 승인 근거 인용과 사용자의 수정 요청을 전송합니다. 자동 재시도 없이 한 구좌만 받아 검증하며, 다른 구좌와 승인은 보존합니다. 전체 생성은 모든 구좌가 승인 전인 새 버전을 만들고 이전 버전은 유지합니다. 실제 호출을 켜기 전 요청 예약과 지출 한도를 추가 검증해야 합니다. 디자인 이미지 생성은 아직 구현하지 않았습니다.
